# Session report — 2026-11-11 — Step 5: Zombie AI, animation & networked enemies

## Goal
Zombies that navigate a complex multi-floor test map, tear through barricades, surround and attack players, react to damage (stagger, crawler conversion, gibs) and die with weight (ragdoll pool), simulated on the host and smoothly replicated, within the 32-zombie AI budget. Both checkpoints in one session: **5A** (simulation, navigation, crowd, performance) and **5B** (visual animation, reactions, gibs, audio, replication polish).

## Completed
- **Data:** `ZombieArchetype` (`core/enemies/zombie_archetype.gd`, `content/enemies/zombie/zombie.tres`): 3 model variants (orderly / pallid / frostbitten), 5 locomotion tiers (1.1 / 1.7 / 3.0 / 4.3 / 5.4 m/s, ±8% jitter), attack (50 dmg, 0.45 s wind-up, 1.4 m / 2.0 m sprinter lunge, 1.1 s cooldown), crawler speed/damage, GDD health curve (`health_for_round`), zone multipliers, stagger / crawler / gib thresholds, tear times (1.0 s, 0.8 s at run/sprint), climb time, voice settings. Registered by `Content` automatically.
- **Actor:** `ZombieActor` (`HitTarget`): body capsule on layer 4 (blocks players on every peer), replicated presentation state (speed, tier, action + host-clock start, flags crawler/burning/stunned/traversing/frozen/aggro, health bucket), `client_tick` interpolation, corpses drop collision.
- **Brain (host):** `ZombieSim` — SPAWNING (riser rise 1.2 s / window entry) → PURSUE (path following, final approach to a surround slot) → ATTACK (telegraphed wind-up, damage through the host API) / TEAR (one plank per tear time, one zombie per window) / TRAVERSE (window climb, drop-down, vent crawl along `TraversalLink`s) / STAGGER (hit ≥ 35% max HP) / WAIT (busy window) / IDLE. Crawler conversion on explosive damage below the hips. Target selection by **path distance** at 2 Hz with 3 m hysteresis, downed players ignored. Stuck (< 0.75 m in 4 s away from the target), far (> 60 m path for 8 s) and unreachable (8 s) → re-queue.
- **CrowdDirector:** path-query FIFO with a 6/frame budget, think LOD (0.1 / 0.25 / 0.5 s at < 20 / < 40 / ≥ 40 m), surround slots (8 + 12 rings), spatial-hash separation, navmesh re-projection, per-frame time accounting (avg / p99 / max) shown on the F3 overlay and `ai_stats`, debug drawing.
- **World:** `TraversalLink` (WINDOW / DROP / VENT / JUMP), `Barricade` (6 planks, fling animation, audio, occupant), `NavDoor` (collider toggle + threaded re-bake of the owning region), `ZombieSpawner` (WINDOW / RISER / VENT / DOOR_BURST / SPECIAL + zone id), `WorldSync` (tree-order ids, `_barricade` / `_door` events, `_world_full` on join). `Match` now creates `WorldSync` and `ZombieSync`.
- **Replication:** `ZombieSync` — NetIds, `_zspawn` / `_zdie` (gib mask + impulse direction) / `_zdespawn` / `_zfull`, 20 Hz `ZombieSnapshot` stream (15 B per zombie), target ids `10000 + NetId`, re-queue respawn at the path-nearest spawner ≥ 8 m from players (`auto_respawn` until Step 6's SpawnDirector). Grenade splash now carries its position (crawler rule).
- **Visuals:** `ZombieVisual` — code-built `AnimationTree` (locomotion blend + rate matching, crawl, death, action one-shot seeked to the replicated start time, upper-body hit reacts head / left / right / stomach), `LookAtModifier3D` head look ≤ 15 m, animation LOD (every 1 / 2 / 4 frames), rise from the floor, `GibModifier` (head / forearm / shin collapse) + pooled gib chunks, ragdolls (`PhysicalBoneSimulator3D`, 11 bones) with the 6-ragdoll budget in `ZombieFx` (oldest frozen), corpse sink + free.
- **Audio:** `ZombieAudio` — procedural placeholder voices (3 groans, scream, attack, pain, death), footsteps, tear, gib, body fall, barricade tear/repair, door open/close; voice priority (max 10, nearest steals) — all as `Audio` events; `Audio.play_event_3d` gained a pitch parameter (per-zombie voice pitch).
- **Test map:** `maps/_test/nav_torture.tscn` (`--map=nav_torture`): 3 floors, stepped stairs, ramp, 1.2 m corridor and doorway, crates, 2 toggle doors (D1, D2), balcony drop link, vent duct link, 2 barricaded windows into an enclosed yard, 13 spawners, floor targets, bot route, 3 screenshot cameras. Navmesh baked at load (agent r 0.3 m, h 1.8 m, climb 0.3 m, 40°; cells 0.15 / 0.1 m set as the project defaults).
- **Console:** `spawn_zombie <tier> [n] [spawner|front|<name>]`, `zombie_freeze`, `zombie_debug` (paths, links, targets, state labels), `kill_all`, `zombies`, `ai_stats`, `zombie_crawler`, `barricade <planks>`, `door <name> <open>`; overlay AI line.
- **Tools:** `run_sim.sh perf_arena` (CSV) and `run_sim.sh soak`; `net_tests.sh zombies`; `visual_tests.sh zombie_showcase`.

## Decisions & deviations
- D-033 … D-039 (ARCHITECTURE §14): navmesh-constrained kinematic zombies; CrowdDirector with custom separation + surround slots **instead of NavigationAgent3D RVO**; TraversalLink + Barricade + NavDoor re-bake; ZombieSync protocol and quantized snapshots; WorldSync; code-built AnimationTree with **blended (not additive) upper-body hit reacts**; physical-bone ragdolls with a frozen-in-place overflow.
- Agent radius is 0.3 m (2 navmesh cells) instead of 0.35 m: Recast ceils the radius to whole cells; the archetype capsule matches.
- perf_arena's "4 bot players" are the local avatar plus 3 scripted target markers looping routes on each floor (the AI cost is the same per target; real extra avatars only add player-physics cost, which is not part of the AI budget).
- The soak runs 600 **simulated** seconds with `--fixed-fps 60` (2.5 min wall time).
- Deferred (PROGRESS *Deferrals*): foot-placement IK (Step 13), RVO avoidance (only if playtests need it), extra zombie clips (Steps 12/13), swipe-through-window attacks + plank rebuild (Step 6).
